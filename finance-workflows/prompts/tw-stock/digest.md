# 逐字稿讀取規則（前置步驟：必須在產報告之前完成）

在產出 HTML 報告之前，**先**把 Eason 今日影片的逐字稿完整讀進工作記憶。**不要寫任何 transcript-digest 檔案到磁碟**；本工作流只跑一個 `claude -p` turn，逐字稿在這一輪 in-context 就是真實依據。

## 步驟

1. 從 `${SOURCES_JSON}` 找出 `kind=="youtube"` 的 source，取它的 `handle` 欄位（例如 `@m168`）。
2. 呼叫 `mcp__yt-dlp__ytdlp_latest_from_channel(handle=<上一步的 handle>, max_results=3)`。**不要**用 `ytdlp_search_videos` —— handle 的關鍵字啟發式會把它搜成不相關頻道。
3. 從回傳列表挑日期最新那筆（優先 `upload_date == ${DATE}`，沒有就用排在最前面的最新一筆）。記下 `video_url`、`title`、`upload_date`。
4. 對選定的影片從 `page=0` 起呼叫
   `mcp__yt-dlp__ytdlp_transcript_page(video_url=<url>, page=<n>, page_size=12000)`，
   讀回傳的 `total_pages`，**逐頁呼叫到 `page == total_pages-1`**，把每頁 `text` 在工作記憶中**完整串接**成整份逐字稿。**不可只看第一頁就下結論。**
5. 心中（在後續推理時）依下方 schema 結構化今日重點，作為寫報告的依據；**不需要也禁止**把它 `Write` 成檔案。

## 在工作記憶中要結構化保留的資訊

- **影片清單**：標題 ｜ video_id ｜ url ｜ 逐字稿來源（captions / gemma4:e4b / none）｜ 完整字元數
- **Eason 總體市場立場**：看多／看空／中性 + 1-2 句理由，僅依逐字稿
- **選股清單**：標的名稱 ｜ 代號 ｜ 方向（看多／看空／觀望）｜ Eason 理由（濃縮）。只列 Eason **明確**點到的個股；沒講代號就留空；不確定就不要列。
- **五層邏輯鏈要點**：宏觀／資金面、產業／族群、個股、風險、操作／選股方向，各 2-4 條 bullet
- **風險提示**：Eason 實際提到的風險，逐條
- **關鍵原話逐字引用**：5-10 句 Eason 原話，從逐字稿原文**逐字複製**，不可改寫、不可翻譯、不可潤飾

## 忠實度鐵則（違反即任務失敗）

- 只能萃取逐字稿**真實出現**的內容。**嚴禁**臆測、補充、或「合理推論」逐字稿沒講的數字、個股、結論。
- 不確定 → 省略，不要硬填。寧缺勿假。
- 「關鍵原話逐字引用」必須是逐字稿原文的逐字片段，一字不改。
- 即使逐字稿 `source` 為 `none` 或抓不到內容，仍要繼續流程：在報告中標註「逐字稿不可用」，並在「報告總結」明確降低信心值（0-10 中的低端）。

## 限制

- 本前置步驟只允許 `mcp__yt-dlp__*`。**禁止** Bash／其他 MCP 在這個階段被呼叫。
- **完全禁止**用 `Write` 或 `Bash` 把逐字稿／digest 寫到磁碟；逐字稿留在工作記憶即可。
- 讀完整個逐字稿後再進入下一份 prompt（transcript.md → main.md）的指示，**不要**只讀一頁就跳去寫報告。
